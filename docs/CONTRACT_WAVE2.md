Extends `docs/CONTRACT.md` (all its rules apply). `docs/API.md` describes what wave 1 built (auth, admin users, events, SSE, callbacks, results, drafts, shifts, export).

## Overnight

- `POST /api/overnight/{id}/confirm` (overnight.manage, booking, status new -> confirmed; outbox sms would_send "confirmation"; event "Priya confirmed Tran for Thu Oct 29, 9:30 am"; toast text in UI "Confirmation text sent (mock). Now enter it in ImproMed.")

## Simulator ("Try it as a client"), engine in `backend/app/aftercare/`
- `POST /api/sim/start {"channel":"text"|"call"}` (sim.use) -> `{"session":{id, channel, node, messages:[{who:"bot"|"client", text}], options:[{index,label}], done:false, accepts_text:true}}`
- `POST /api/sim/{id}/reply {"option_index":int}` or `{"text":str<=500}` -> same shape; when done, also `"outcome":{"kind":"booking"|"callback"|"emergency","conversation_id":..}`. A session belongs to its creator (others get 404).
- Engine is pure Python and deterministic: `aftercare/engine.py` with `start(channel, ctx) -> State` and `step(state, input, ctx) -> (State, [bot_texts], outcome|None)`, where `ctx` carries settings (toggles, bookable visit types, open future slots, confirmed hospitals, keyword list, clinic name, layer2 callable or None). The same engine powers `/api/sim`, the Retell functions and `eval/run_eval.py`.
- Nodes and wording: as the reference `SIM` object. Opening line: "Hi, this is the automated assistant for {clinic_name}. The clinic is closed until 8 am. I can take an appointment request or pass on a message. What do you need?" In call mode prepend "This call is recorded." after the greeting sentence. Slots come from `open_slots` (future only, not taken, filtered by visit type minutes), formatted like "Thu Oct 29, 9:30 am". If the take-requests toggle is off, booking paths become callbacks. If take-messages is off, refill/message paths say the clinic will be closed and to call back after 8 am, and still log a callback for staff.
- Emergency detection `aftercare/emergency.py`: `detect(text, keywords, layer2=None) -> {"emergency":bool,"matched":[...],"layer":"1"|"2"|"unsure"|None}`. Layer 1: lowercase, strip punctuation, collapse spaces, also match simple variants (plural, -ing) and phrase lists; each keyword entry may be a plain phrase or a `re:` regex. Every client text input (free text or option label) is checked first, on every node. If layer2 is provided and returns "unsure" or raises, treat as emergency. Option "Something urgent" / "Yes, it is urgent" routes to emergency directly.
- Emergency response: if at least one hospital is `confirmed` and not placeholder: "That sounds like it needs a vet now. {name} in {place} is on the clinic emergency list{hours_part}. " + ("Their phone number is {phone}. " if phone) + ("The address is {address}. " if address) + "Please go now, and call them on the way if you can. The clinic will check in with you in the morning." where hours_part = " and says it is open 24 hours" only when hours_claim mentions 24 hours. If none confirmed: "That sounds like it needs a vet now. Please contact the nearest emergency veterinarian right away. The clinic will follow up with you in the morning." Never invent numbers or addresses.
- Advice guard: texts asking for dose, medicine amount, whether the pet is okay, what to give, diagnosis (`how much`, `mg`, `dose`, `can i give`, `is it safe`, `should i worry`, `is he ok`, `what is wrong`, etc, in a `ADVICE_PATTERNS` list) get: "I am an automated assistant and I cannot give medical advice or medicine amounts. If you are worried about your pet right now, please contact an emergency veterinarian. I can also pass a message to the clinic team for the morning." then continue with options (message or urgent). The engine never emits text that is not from `aftercare/templates.py`. Add a test that every emitted string is a rendered template.
- Free text intent (rules only): booking words (book, appointment, check-up, checkup, vaccine, shots, visit, exam), refill words (refill, medication, medicine, pills, prescription, food, order), cancel/reschedule -> callback, anything else -> message callback.
- Outcomes write: `conversations` (source sim, is_test true, client_label "You (test)"), plus `appointment_requests` (booking), `callbacks` (refill/message/another day; what = summary + " Taken overnight by the assistant."), `emergency_routings` (emergency), and an event in tool "After-hours assistant": "New appointment request from a test client" / "New callback from a test client" / "New emergency routing from a test client".

## Brief and suggestions (`backend/app/rules/`, `backend/app/services/metrics.py`)
- `GET /api/brief` (brief.view) -> `{"greeting":"Good morning, Dr. Garg","date_line":"Tuesday, October 27. Here is what the front desk and nurses logged since yesterday.", "kpis":[{"key","value","label","alert"}], "overnight":{...summary as above}, "suggestions":[{id,rule_key,title,why,status,evidence}], "chart":{"mode":"real"|"example", "available_modes":[...], "hours":["8a",...,"5p"], "calls":[float], "cover":[int], "per_person":[float], "limit":12, "calls_label":"Real recorded call volume, average weekday" | "Example numbers", "cover_label":"Assumption: example roster"}, "text":{"source":"template"|"model","paragraph":str}}`. Query param `?chart=real|example`. Real mode uses `call_analytics` rows `metric="weekday_avg_calls_by_hour"` dim1 = hour "8".."17"; if absent, only example mode is available. Cover per hour = number of desk or open shifts covering that hour, averaged Mon to Fri, from `shifts` (so approving the desk shift really lowers the bars).
- KPIs: open callbacks (alert if any high open), results waiting 2+ days (alert if > 0), missed calls last week (from `imported_calls` visible rows with outcome no_answer or voicemail in the last 7 days if any exist, else from `call_log_demo`; label says "(example)" when demo), overnight items to review (alert if > 0).
- `call_log_demo`: seeded synthetic rows (source demo) so that last week has 41 missed calls, the week before 32, 28 called back within the hour, 13 never did, gaps Tue and Thu 8 to 10 and Sat 9. Recall bookings 18 both weeks. Use these for the assistant's "missed" and "week" answers.
- Rules `rules/engine.py`: `run_rules(db, settings) -> created suggestions`, idempotent per rule_key while one is open or approved within 7 days. Thresholds in settings key `rules`: `{"load_limit":12,"min_weekdays":3,"missed_min":20,"recall_min":50,"recall_batch":10,"results_age_days":2}`. The seed inserts the reference's four suggestions directly (the demo story), and `run_rules` can add more later. Overdue recalls count = `pims_patients` with last_exam older than 13 months, else 120 from the demo constant labeled example.
- `POST /api/suggestions/{id}/approve` (suggestions.decide): effects exactly as reference: desk_shift adds `open` desk shifts 08:00 to 10:00 Mon to Fri with proposed=true (event Staff roster "Dr. Garg approved an open desk shift, 08:00-10:00, Monday to Friday"); missed_texts sets toggle missed=true (event Callback list "Dr. Garg turned on texts to missed callers"); recall_batch inserts RECALL_EXTRA_DRAFTS (event Recall sender "Recall batch started: first drafts sent to the front desk for approval"); old_results sets stage 0 with age >= results_age_days to stage 1 (event Results tracker "Dr. Garg marked older results as reviewed, nurses can call clients"). `POST /api/suggestions/{id}/dismiss`. `POST /api/suggestions/run` runs rules.
- Brief paragraph: templated by default from metrics. If AI "word the brief" toggle is on and a key is set, ask the model to rewrite the templated paragraph (only metrics sent, no names), then `services/numbercheck.py: check(text, allowed_numbers) -> (ok, bad_numbers)` extracts every number (digits, decimals, percents, times like 9:30, and number words zero to one hundred) and rejects the text if any is not in the allowed set (allowed = all metric values plus their int/rounded forms plus clock times present in the metrics). Rejected -> template, and an event "Brief wording rejected: number not in the record".

## Assistant panel (`backend/app/assistant/`)
- `GET /api/assistant/chips` (assistant.use) -> `{"greeting":str,"chips":[{"key","question"}]}` per role from seed CHIPS/GREETINGS.
- `POST /api/assistant/ask {"key"?:str, "text"?:str<=300}` -> `{"answer":{"paragraphs":[str], "bullets":[str], "after":[str], "link":{"label","view"}|null, "source":"record"|"answer_sheet"|"fallback"}}`. Plain text only (no HTML). Each key is a handler that queries the DB and fills the reference wording with real numbers and names from the demo record. Keys: night, emerg, first, missed, recall, saturday, week, urgent, records, hours, pickup, waiting, script, flags. `pickup` really creates a pending draft for Pepper (Ready for pickup) if none pending. `script` uses "[what Dr. Garg wants said]" instead of a finding. `records` and `hours` come from settings key `answer_sheet` (seeded with the reference text, marked example). Free text: the reference `guess()` keyword table; no match -> source fallback: "I can answer questions about: " + the role's chip questions.
- Role check: a key not in the caller's role chips returns 403.

## Admin: AI provider and Retell settings
- `GET /api/admin/settings/ai` -> `{"provider":"off"|"deepseek"|"openrouter","base_url","model","key_set":bool,"key_last4":str|null,"word_brief":bool,"emergency_check":bool,"allow_transcript_labeling":bool,"warning":str}`. Defaults: provider off, deepseek base_url https://api.deepseek.com, model deepseek-chat; openrouter base_url https://openrouter.ai/api/v1. The warning text: "DeepSeek processes data on servers outside Canada. Only turn on transcript labeling after Dr. Garg has decided this is acceptable under BC privacy law."
- `PUT /api/admin/settings/ai {provider?, base_url?, model?, api_key?, word_brief?, emergency_check?, allow_transcript_labeling?}`: key stored Fernet-encrypted in settings; never returned. On save, write `WALNUT_LLM_ENV_PATH` (mode 0640) with `PROVIDER=, BASE_URL=, MODEL=, API_KEY=, ALLOW_TRANSCRIPT_LABELING=0|1`. `POST /api/admin/settings/ai/test` makes one tiny chat completion ("Reply with OK") and returns `{"ok":bool,"detail":str}`. `adapters/llm.py: LlmClient.from_settings(db) -> client|None` with `complete_json(system, user, timeout)`; all calls time out at 15 s and never log bodies.
- Retell settings: `GET/PUT /api/admin/settings/retell {enabled, dry_run, regenerate_secret?:bool, retell_api_key?}` -> on regenerate returns the new secret once. Stored hashed (sha256) plus Fernet for the api key.

## Retell hook (`backend/app/retell/`)
- All routes 404 unless enabled. Header `X-Walnut-Secret` required (constant-time compare against stored hash) else 401. If a Retell API key is configured, also verify `x-retell-signature` per Retell's documented scheme in `retell/verify.py` (keep it isolated; document what you verified and from which docs).
- Internal schema `retell/schema.py`: function calls arrive as `{"call_id":str, "name":str, "args":{...}}` (Retell custom functions post `{"call": {...}, "name": ..., "args": {...}}`; `retell/mapping.py` converts). Responses are `{"result": {...}}` small JSON the voice agent can read.
  - check_emergency `{text}` -> `{"emergency":bool,"matched":[..],"say":str}` (say = emergency template or empty)
  - get_open_slots `{visit_type?, after?}` -> `{"slots":[{"id","label"}]}` (max 3, future only)
  - create_appointment_request `{client_name, pet_name, visit_type, slot_id, phone_last4?}` -> `{"ok":true,"say":"I have asked for ... The front desk will confirm after 8 am."}` creates a conversation (source retell) + appointment_request
  - create_callback `{client_name, pet_name?, reason}` -> `{"ok":true,"say":...}` creates a callback
  - get_emergency_hospital `{}` -> `{"confirmed":bool,"say":str}` (same template rules)
  - webhook `{"event":"call_ended","call":{"call_id","transcript","call_analysis":{"call_summary"}, "start_timestamp","end_timestamp"}}` -> stores an overnight conversation (channel Call, source retell, summary from call_summary, messages parsed from transcript lines "Agent:"/"User:"). Other events -> 204.
- In dry_run, functions still create rows but mark them is_test and all outbound goes to outbox would_send. Nothing ever places a call or sends a text.

## Import and PIMS
- `POST /api/admin/import/{kind}` multipart file (csv or jsonl, <= 10 MB), kind in `calls, appointments, clients, pets, lab_results, analytics`. Per-row pydantic validation, returns `{"accepted":n,"rejected":[{"row":i,"error":str}] (first 50), "kind"}` and an event "Imported 64 appointments (read only)" in tool ImproMed sync (calls/analytics use tool Call logger).
- `calls` schema exactly: `call_id, timestamp (ISO), caller_type, intent, outcome, urgency, red_flags (JSON list or ;-separated), promised_followup (bool), contains_private_content (bool), summary`. Rows with contains_private_content true are stored with summary set to NULL and excluded by the `visible_calls` SQL view; every metric and list reads the view.
- `analytics` rows: `source, metric, dim1, dim2, value, n` (source must be `derived_from_real_calls` or `demo`). Importing analytics replaces existing rows of the same source. JSON file form `{"meta":{...},"rows":[...]}` is also accepted.
- `adapters/pims.py`: `class PimsAdapter(Protocol)` with `appointments(day)`, `clients()`, `patients()`, `lab_results(since)`; `CsvExportAdapter(dir)` reads `appointments.csv, clients.csv, patients.csv, lab_results.csv`. `python -m app.pims_sync --dir samples/pims` loads into `pims_*` tables (read only) and writes the ImproMed sync event.
- `samples/`: `calls.csv`, `calls.jsonl`, `analytics.json`, `pims/appointments.csv`, `pims/clients.csv`, `pims/patients.csv`, `pims/lab_results.csv`, all invented.
- Exports: add `overnight` and `analytics` to `/api/export/{name}.csv`.
